# v1.3 — benchmark

Status: in progress. Follows v1.2 (run gateway).

## Intent

A success rate the registry measured itself, by calling the agent with
known inputs and checking the answers, shown next to the security grade.
Availability (gateway ok-rate) and correctness (benchmark pass rate) are
different numbers; both are displayed and labelled.

## Why author-declared cases

Agents do not share an input schema, so a registry-owned task set per
category cannot be sent to arbitrary agents. In v1.3 the author declares
test cases in the manifest; the registry runs them through the gateway,
adds its own generic probes, and publishes the result. Declaring a case
is not the same as declaring a result: the author cannot skip the run.
Category task sets can come once categories converge on schemas.

## Manifest (`spec.tests`, optional, max 10)

```yaml
spec:
  tests:
    - name: explain a slow join
      input: { sql: "select * from orders o join customers c on c.id = o.customer_id where c.country = 'FR'" }
      expect:
        status: 200            # default 2xx
        contains: "CREATE INDEX"   # substring of the JSON-serialised output
        jsonPath: { path: "suggestions.length", min: 1 }   # optional, simple dotted path
        maxLatencyMs: 8000
```

## Registry probes (always run for runnable agents)

- `liveness`: `{}` → any JSON answer, no 5xx, under 10 s.
- `malformed`: body `{"__agenthive_probe": "unexpected"}` → must not 5xx.
- `latency`: the mean of the author cases stays under 10 s.

## Execution

- Trigger: after a successful publish (background via `waitUntil` on
  Vercel, inline in dev/tests), by the owner (`POST
  /api/v1/agents/:name/benchmark`, 1/h), and daily by a cron
  (`GET /api/cron/benchmark`, header `authorization: Bearer $CRON_SECRET`)
  over every runnable agent, which makes the number continuous.
- Calls go through `runAgent` with the system caller `benchmark` and
  `via: 'benchmark'`; they are logged but excluded from quotas and from
  the measured gateway metrics.
- Budget: 10 s per case, 45 s per benchmark, function `maxDuration` 60 s.
- Result stored in `benchmarks` (`id`, `agent_id`, `version`, `passed`,
  `total`, `pass_rate`, `results` jsonb, `trigger`, `created_at`);
  `agents.benchmark_pass_rate`, `benchmark_at` mirror the latest.

## Display

- Card and overview: "success" = benchmark pass rate when a benchmark
  ran, labelled "benchmark, N cases"; gateway ok-rate shown as
  "availability" on the overview. Seeds keep illustrative numbers.
- Overview gets a "Benchmark" section: per case pass/fail, latency,
  reason, last run, trigger.
- Dashboard: "run benchmark" per agent.
- `GET /agents/:name/benchmark.json` public. Agent card `x-agenthive.benchmark`.
- CLI: `agent-cli benchmark <name> [--run]`.

## Out of scope

Leaderboard page (v2), category task sets, LLM-judged outputs.
