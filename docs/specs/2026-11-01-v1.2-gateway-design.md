# v1.2 — run gateway

Status: in progress. Follows v1.1 (computed grades).

## Intent

`POST /api/v1/run/<name>` lets anyone with an AgentHive API key call an
agent through the registry. AgentHive does not host agents: it forwards the
call to the author's declared `spec.endpoint`, enforces quotas and
timeouts, signs the request so the author can verify it came through the
gateway, logs every call, and turns those logs into the agent's measured
numbers (runs, success rate, latency). The author keeps the runtime; the
registry keeps the relationship, the data and the trust signal.

## Scope

In: synchronous proxying for `transport: a2a/http+json`, per-key and
per-agent quotas, request signing with a per-agent gateway secret, run
logs with an owner console and a caller history, measured metrics on the
card and in the index, CLI `run`, a public echo endpoint for testing.

Out: async runs and completion webhooks, streaming, billing, MCP/stdio
agents (no endpoint to call), retries after the upstream has received the
body.

## Request path

1. Auth: API key (`Authorization: Bearer ah_…`) or session. Anonymous → 401.
2. Agent must exist, not be a seed, have `transport: a2a/http+json` and an
   `endpoint`. Otherwise 409 with a reason.
3. Quotas, counted from the `runs` table: 60 runs per minute and 500 per
   day per caller; 2 000 per day per agent. Exceeded → 429 with
   `retryAfterMs`.
4. Request body: JSON only, 256 KiB max. Forwarded verbatim.
5. Upstream call through the audit's safe fetch (https only, public
   addresses pinned at connect time, no redirects), 20 s timeout, response
   body capped at 1 MiB. One retry only on connection errors before any
   byte was sent.
6. Headers sent upstream: `content-type: application/json`,
   `x-agenthive-run-id`, `x-agenthive-caller` (login),
   `x-agenthive-agent` (`name@version`), `x-agenthive-timestamp`,
   `x-agenthive-signature` = hex HMAC-SHA256 over
   `${timestamp}.${body}` with the agent's gateway secret.
7. Response: upstream status and JSON body passed through (non-JSON →
   502 `upstream returned non-json`), plus `x-agenthive-run-id` and
   `x-agenthive-latency-ms`.
8. Log row written whatever happened.

## Data

- `agents.gateway_secret` (text, generated at first publish, rotatable by
  the owner, shown in the dashboard).
- `runs`: `id`, `agent_id`, `agent_version`, `caller_id`, `caller_login`,
  `via` (`api-key` | `session`), `status` (`ok` | `upstream_error` |
  `timeout` | `blocked` | `bad_request`), `http_status`, `latency_ms`,
  `request_bytes`, `response_bytes`, `error`, `created_at`. Index on
  (`agent_id`, `created_at`) and (`caller_id`, `created_at`).
- Measured metrics for non-seed agents are computed from `runs` over 30
  days at read time: `runs30d` = count, `successRate` = ok / total when
  total ≥ 20 (else null), `avgLatencyMs` = p50-ish mean of ok runs.
  `costPerRun` stays null (no billing yet).

## API

- `POST /api/v1/run/:name` — as above.
- `POST /api/v1/echo` — public test upstream: echoes the JSON body with the
  gateway headers it received (signature verified when `x-agenthive-*`
  headers are present and the secret is known, i.e. only for the demo
  agent). Documented as "point your first manifest here".
- `GET /api/v1/agents/:name/runs` — owner: last 100 runs.
- `GET /api/v1/agents/:name/secret` / `POST …/secret/rotate` — owner.
- `GET /api/v1/runs` — caller: last 100 runs I made.

## UI

- Drawer "Run" tab for runnable agents (endpoint + a2a transport, not a
  seed): JSON input, Run (sign-in required), response, latency, run id.
  Seeds keep the simulated sandbox, still labelled.
- Dashboard: per agent, gateway secret (reveal/rotate, with the signature
  recipe), last runs.
- Card metrics show "measured" vs "illustrative".

## CLI / packages (0.3.0)

- `agent-cli run <name> [--input '{…}' | --input-file f]` prints the JSON
  response; `agent-cli runs [name]` lists runs (owner or caller view).
- registry-client: `run(name, input)`, `runs(name?)`.

## Testing

- Server tests with an injected upstream fetch: happy path, signature
  verified by a fake upstream, non-json upstream, timeout, 5xx, quota per
  minute, agent without endpoint, seed, blocked private host, logs written,
  metrics computed after 20 runs.
- e2e: publish a manifest whose endpoint is the production echo
  (`https://agenthive.sh/api/v1/echo`), run it from the Run tab, see the
  echoed input and a run id, then see the run in the dashboard.

## Decisions

- Quotas from the database rather than memory, so they hold across
  function instances; the counts are indexed and cheap at this volume.
- HMAC with a per-agent secret instead of mTLS or OAuth: one line to
  verify in any language, rotatable, no coordination.
- Measured numbers replace declared ones only for non-seed agents; the
  seeds stay illustrative and labelled.
