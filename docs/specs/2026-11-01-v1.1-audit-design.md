# v1.1 — computed grades

Status: in progress. Follows v1.0 (`2026-10-31-v1-registry-design.md`).
Public criteria live in `docs/GRADING.md`; this document covers the build.

## Intent

Replace `grade: pending` with a grade the registry computes from verifiable
checks, at every publish, with a public report. This is the registry's
reason to exist: a trust signal nobody else provides for agents.

## Scope

In: static checks on the manifest, the declared endpoint and (optionally)
the public source repository's dependency manifests; grading; audit report
storage and display; re-run; CLI output.

Out: executing agents, reading private code, prompt-injection detection
(not reliably checkable), anything that needs the run gateway.

## Manifest additions (still `agenthive.sh/v1`, both optional)

- `spec.permissions`: `{ network: string[] | ["*"], filesystem: "none" | "read" | "write", shell: boolean, env: string[] }`
- `spec.source`: `{ repo: https URL, ref?: string, path?: string }` — GitHub
  only in v1.1; other hosts produce a low finding "unsupported host".

## Audit engine (`server/audit/`)

- `types.ts` — `Finding { check, severity: 'blocker'|'high'|'medium'|'low', message, hint? }`,
  `Report { version, score, grade, caps, findings, checks: {id, status, ms}[], auditedAt, engine: 'v1' }`.
- `checks/*.ts` — one module per check, pure where possible; network checks
  take `fetch`, `lookup` and a deadline through `AuditContext` so tests use
  fakes and production uses real ones with a 4 s per-call timeout and an 8 s
  total budget (the Vercel function has 10 s on this plan).
- `grade.ts` — score, caps, grade as in GRADING.md. Deterministic, tested.
- `index.ts` — `runAudit(manifest, ctx)`; a check that throws or times out
  yields `status: 'error'` and a low finding "check did not complete", never
  a crash.

Secrets patterns: AWS access key ids, GitHub tokens (`ghp_`, `gho_`, `ghs_`,
`github_pat_`), OpenAI/Anthropic keys, Slack tokens, Stripe live keys, Google
API keys, PEM private key blocks, JWTs, `scheme://user:password@host`.

Endpoint: hostname must not be an IP literal in private, loopback,
link-local or metadata ranges; the resolved addresses must not be either
(DNS rebinding is out of scope, the registry never calls the endpoint again).
Then `GET <endpoint>` and `GET <origin>/.well-known/agent.json`.

Dependencies: `GET https://raw.githubusercontent.com/<owner>/<repo>/<ref>/<path>/package.json`
(and `requirements.txt`, `pyproject.toml`), parse pinned versions only, batch
query `https://api.osv.dev/v1/querybatch` (max 100 packages), map severity.

## Data

- New table `audits`: `id`, `agent_id`, `version`, `grade`, `score`,
  `report` (jsonb), `created_at`. Latest per agent is the one whose
  `created_at` is greatest; `agents.grade` mirrors it, `agents.audited_at` set.
- Seeds get no audit row; their report is synthesised (`illustrative: true`).

## API

- Publish: audit runs after validation, before the insert. Blockers → 422
  with `{ error: 'audit blocked', findings }`, nothing stored. Otherwise the
  agent row and version are written, then the audit row, and `grade` set.
  If the engine fails entirely, the agent is stored with `pending`.
- `GET /agents/:name/audit.json` — public, cached, latest report.
- `POST /api/v1/agents/:name/audit` — owner only, re-runs on the stored
  manifest, 1 per hour per agent.
- Agent card gains `x-agenthive.audit: { grade, score, auditedAt, report }`.
- Registry index gains `score` and `auditedAt`.

## UI

- Drawer: new "Audit" tab (score, grade, caps explained, findings grouped by
  severity, per-check status, link to GRADING.md). Grade badge tooltip says
  "computed by the registry" or "illustrative seed".
- Publish form: collapsible "Permissions & source" section.
- Dashboard: audit grade + "re-run audit" per agent.
- Publish success: shows grade and top findings.

## CLI / packages

- `agent-cli push` prints grade, score and findings.
- `agent-cli audit <name> [--rerun] [--json]`.
- registry-client: `audit(name)`, `rerunAudit(name)`, types. Packages bump
  to 0.2.0; generated snippet pins move to 0.2.0.

## Testing

- Unit: each check with fixtures (fake fetch/lookup), grading table, secrets
  corpus (true positives and benign near-misses such as `sk-` in prose).
- Server: publish with a secret → 422; publish without permissions → grade
  capped AA; with fake GitHub + OSV responses → AAA / high finding paths.
- e2e: publish from the UI shows a computed grade; Audit tab renders.

## Decisions

- Synchronous audit inside the publish request, with budgets, instead of a
  queue: no queue infrastructure exists yet and the checks are bounded.
- GitHub-only source in v1.1. Tarball upload and other hosts later.
- Caps instead of penalties for unverifiable items, so an honest minimal
  manifest lands at A, not B.
