# Plain language rules

## Order

1. Action and deadline first.
2. Then the reason, in one sentence.
3. Then the exceptions.
4. Then where to get help.

## Sentences

- One idea each. Split at "and", "which", "in order to", semicolons.
- Active voice with the actor named: "We pause your access" not "Access privileges may be subject
  to suspension".
- Verbs, not nouns made from verbs: decide not "make a decision", apply not "submit an
  application", sign in not "complete the authentication process".
- Cut: "pursuant to", "aforementioned", "in accordance with", "hereby", "please note that", "it is
  important to", "in order to", "at this point in time", "prior to" (before), "subsequent to"
  (after), "utilise" (use), "facilitate" (help), "commence" (start), "terminate" (end).

## Words

| Instead of | Write |
|---|---|
| individuals, users, personnel | you, employees, customers (whoever it is) |
| not exceeding thirty (30) days | at least every 30 days |
| failing which | if you do not |
| in the event that | if |
| with regard to | about |
| a number of | some, or the number |

Numbers as digits. Dates with the month spelled. Money with the currency.

## Lists and layout

A list when there are real steps or options, three or more. Otherwise prose. Headings only for
texts over 150 words. Bold for the deadline, once.

## Terms

Keep a term when the reader will meet it again elsewhere (in the app, in a contract) and define
it once in plain words. Replace it when it is only formal. Never redefine a legally defined term
in a way that changes its scope; keep it and define it narrowly.

## Protecting meaning

Before and after, list: who, what, when, what if not, exceptions. Each item must map one to one.
"May" versus "must" is a meaning difference; keep it. If the original is ambiguous, keep the
ambiguity and raise it in `questions` rather than resolving it silently.
